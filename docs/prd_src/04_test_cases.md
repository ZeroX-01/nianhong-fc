# 自动化测试体系事实汇总

本文档详细记录了《那年的红白机》自动化测试系统的架构、方法论及具体测试用例。表中的通过情况均为 2026-09-19 实测值。

## 1. 测试方法论

本系统基于 **Playwright** 构建无头自动化测试，核心设计原则如下：

- **端到端仿真**：完全模拟玩家操作（键盘按键、鼠标点击、触屏），不直接调用内部逻辑函数。纯数值规则（砍价、修卡衰减、存档迁移）例外，它们没有界面可点，在 `page.evaluate()` 里直接调 API。
- **坐标换算**：游戏逻辑分辨率为 480×270，Playwright 视口设为 960×540。所有点击坐标需 **×2** 后发送给浏览器；较新的脚本改用 `canvas.getBoundingClientRect()` 再按 `box.w / 480` 算缩放，更抗窗口变化。
- **调试钩子**：
    - `window.SB.__menu`：读取当前 UI 菜单实例；`menu.debug()` 返回 `{ cur, labels, dis }`（光标位置 / 全部选项文字 / 哪几项已灰），用例按**选项名**定位，不猜行号。
    - `window.SB.__dialogOpen`：对话框开启计数（>0 即开着）。
    - `window.SB.__interludeOpen`：过场摘要（三行 interlude）开启计数。
    - `scene.hint.full()`：底部键位提示条的完整文字。
- **剧情门禁短路标记**（均为存档字段，必须在 `Save.reset()` **之后**设置，否则被冲掉）：
    - `__nostory`：一键短路序章门禁，标题直接进客厅，不落盘。出处 `TitleScene.js` 的 `needPro = !s.flags.prologue && !s.__nostory`。
    - `__nomom`：妈妈不回来，用于专心测别的机制。
    - `seenIntro`：跳过客厅那七句开场。
- **截图机制**：测试脚本运行过程中，各关键节点会截图落盘至 `tools/gametest/<script_name>/` 目录下。
- **端口约定**：多数脚本端口**写死**（`8100`，坦克 `8102`、马里蘑 `8103`、拳霸 `8104`、修卡动画默认 `8110`），命令行传参无效；仅 `prologue_test` / `prologue_shots` / `bugfix_title_room_test` / `move_input_test` 支持传端口或直接传线上 URL。详见 [`../TESTING.md`](../TESTING.md) §2.3。

## 3. 故障对症下药机制 (flow_test.js)

`flow_test.js` 实现了动态故障处理逻辑，以规避花屏故障随机性导致的测试不稳定性 (Flake)：
- **原理**：脚本读取 `window.SB.Save.d.fault` 获取当前随机生成的故障码。
- **映射关系**（与 `SB.FAULT` 表一致）：
    - `SNOW` (雪花没信号) → `reseat` (插拔，由插回动作完成)。
    - `GLITCH` (花屏彩条) → `blow` (哈气)。
    - `ROLL` (滚屏偏色) → `rub` (划桌)。
    - `SHAKE` (抖动横条) → `slap` (拍电视，优先在客厅执行)。
    - `RAINBOW` (彩虹纹) → `puff` (吹卡槽的灰)。
- **逻辑控制**：若拍电视 2 次无效，则强制进入修卡台。这种「对症下药」模拟了真实玩家的行为，确保了测试在复杂随机状态下的收敛性。
- **副作用**：每次跑的路径与修卡轮数都不同，不要拿它的日志做逐行 diff。

## 4. 专项脚本说明
- `prologue_test.js`：序章（2026 那个晚上）的主力回归，63 条断言分六组——结构 / 正着看（含节奏与等车）/ 跳过 / 老档 / 回忆册 / 门禁。分组明细见 [`../TESTING.md`](../TESTING.md) §4。
- `prologue_shots.js`：序章 12 镜逐镜出图。**按快门前必须先 `clearLineTimers()` 把打字机停掉**，否则拍到半行字或下一镜画面。
- `story_core_test.js`：这一版新主线的规则层（借来的机器、45 块二手主机、账本、心情、结局四变体、老档迁移），不截图只跑规则。

- `tank_test.js` / `tank_unit.js`：验证铁甲坦克的碰撞算法、地图销毁、道具与 AI 行为。`tank_test.js` 对 `test-game.html` 的三处已知环境差异做运行时打补丁，并单独归类为 `foreign`。
- `fight_test.js`：验证格斗游戏的招式判定、连段计算与 AI 指令解析。
- `check_mario_map.js`：唯一不需要服务器的脚本，静态校验关卡字符图（每段 17 行、行长不超段宽）。
- `gamekeys_test.js` / `move_input_test.js`：按键指引与移动输入的专项，是「玩家第一次上手会不会懵」这条线的主力。`gamekeys_test` 的 RESET 段本身带概率（拔插复位不一定每次都把卡搞坏），脚本里靠多试几次 + 拉长等待收敛，偶发失败先重跑那一段再判断。
- `staff_test.js`：标题屏那页藏起来的制作名单（秘技 ↑↑↓↓←→←→）的专项。它自己起服务器，并且会先核对 `document.title` —— 端口被别的项目的服务器占着时，`python3 -m http.server` 是静默失败的，不核对就会得到一整片假失败。
- `rescue_test.js`：抢救那三下的专项（37 条断言），覆盖进出条件、三档判定、时间惩罚、三种结算等级和压力缩放。规则层在 `SB.Rescue`，界面在 `PlayScene`，两边都过一遍。
- `tools/check_words.py` / `tools/check_font.py`：发布前的两道体检，不进浏览器。前者扫上屏文案里的商标词 / 真实作品名 / 内部信息（比对转小写，必须留原文的行写 `check-words: allow`），后者保证源码里出现的每个非 ASCII 字符在两套点阵字库里都有图，避免「上屏是空白方块」这种静默失败。
